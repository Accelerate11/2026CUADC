# 2026 年备赛代码说明

## 文件夹说明

此文件夹用于储存 2026 年多旋翼无人机侦察与救援项目的主要备赛代码。

相比 2025 年代码，2026 年的开发环境由 **Ubuntu 20.04 + ROS 1** 更新为：

* Ubuntu 22.04
* ROS 2 Humble
* MAVROS
* ArduPilot / ArduCopter
* Gazebo Harmonic

2025 年代码仍然具有较高的参考价值，尤其是状态机设计、视觉引导、目标搜索和投放流程等部分。但是 ROS 1 与 ROS 2 的节点、话题、服务和编译方式存在较大差异，移植时不要直接复制代码，应当先理解原有逻辑，再按照 ROS 2 的接口重新实现。

目前 2026 年代码主要按照功能划分为 `状态机` 和 `视觉` 两部分。后续版本建议继续采用“模块名称 + 版本号”的方式命名，例如 `状态机1.0`、`视觉1.1`，并在每个版本开头注明代码功能、仿真验证情况和真机验证情况。

## 状态机

### `状态机/offb_node.cpp`

这份代码是 2026 年 ROS 2 自动飞行状态机的基础版本，功能为：

1. 等待飞控连接；
   2.切换至 `GUIDED` 模式；
2. 自动解锁；
3. 自动起飞至 2 m；
4. 飞行一个 5 m × 5 m 的矩形；
5. 回到起点；
6. 自动降落；
7. 结束节点。

代码中的状态依次为：

```text
WAITING_FCU
SETTING_GUIDED
ARMING
TAKEOFF
FLYING_WAYPOINTS
LANDING
DONE
```

相比单纯按照时间切换状态，这份代码已经开始使用飞控反馈判断任务是否完成。例如起飞阶段根据当前高度判断是否到达目标高度，航点阶段根据当前位置与目标位置之间的距离判断是否到达。

矩形航点为：

```text
(0, 0)
(5, 0)
(5, 5)
(0, 5)
(0, 0)
```

当前航点到达误差为 0.5 m。飞机进入航点误差范围并保持约 2 秒后，状态机才会切换至下一个航点，避免因为定位抖动而提前切换。

代码订阅：

```text
/mavros/state
/mavros/local_position/odom
```

代码发布：

```text
/mavros/setpoint_position/local
```

代码调用的主要服务包括：

```text
/mavros/set_mode
/mavros/cmd/arming
/mavros/cmd/takeoff
/mavros/cmd/land
```

这一版比较重要的处理是：使用 ArduPilot 起飞服务时，暂时停止发送位置期望点，避免起飞指令和位置控制指令发生冲突。飞机达到目标高度后，再恢复位置期望点发布。

代码还为起飞设置了 60 秒超时。即使因为高度信息异常没有正常触发高度判断，也可以强制进入航点阶段，避免状态机永久卡在起飞状态。不过真机使用时不能只依赖超时机制，仍需增加更完整的异常处理和人工接管方式。

顶层的 `offb_node.cpp` 适合快速阅读状态机逻辑。需要实际编译和运行时，建议优先使用下面完整工作空间中的版本。

### `状态机/ws_offboard/ws_offboard_2026_6_20`

这是一个能够进行编译和启动的完整 ROS 2 工作空间，主要包含：

* `offboard_control` ROS 2 功能包；
* 状态机节点；
* CMake 和 package 配置；
* SITL 仿真启动文件；
* 真机 MAVROS 启动文件；
* MAVROS 与自动飞行节点联合启动文件；
* 单独启动 offboard 节点的 launch 文件；
* 编译、连接检查、自动飞行和紧急降落脚本。

主要 launch 文件包括：

```text
mavros_offb_real.launch.py
mavros_offb_sitl.launch.py
mavros_real.launch.py
offb_only.launch.py
```

其中：

* `mavros_real.launch.py`：只连接真机 MAVROS，不启动自动飞行；
* `mavros_offb_real.launch.py`：连接真机 MAVROS，并启动自动飞行节点；
* `mavros_offb_sitl.launch.py`：连接 ArduPilot SITL，并启动自动飞行节点；
* `offb_only.launch.py`：只启动状态机节点。

具体的依赖安装、编译命令、串口选择、仿真启动、真机启动和紧急命令，已经写在工作空间内部的 `README.md` 中。使用工作空间前应先完整阅读该文件。

这份工作空间是当前状态机部分最值得参考的内容。后续的目标搜索、危险品识别、航点规划、投放和返航逻辑，都应当在该工作空间的基础上逐步增加，不建议重新从空节点开始编写。

## 视觉

### `视觉/视觉1.0`

视觉 1.0 主要用于危险品目标数据标注和 ONNX 模型实时推理，是 2026 年视觉部分的第一版验证代码。

---

### `dangerous_target.onnx`

危险品识别 ONNX 模型文件。

该模型在 `single_demo_en.py` 中通过 ONNX Runtime 加载，默认使用 CPU 进行推理，便于在 Ubuntu 机载计算机或其他边缘设备上运行。

更换模型后，需要同时检查：

* 模型输入尺寸；
* 模型输出张量格式；
* 类别数量；
* 标签排列顺序；
* 置信度阈值；
* NMS 阈值。

不能只替换 `.onnx` 文件而不检查后处理代码，否则可能出现检测框位置错误或类别对应错误。

---

### `single_demo_en.py`

这份代码用于调用摄像头或视频文件，对危险品目标进行实时检测。

主要依赖：

```bash
pip install opencv-python numpy onnxruntime
```

默认配置为：

```text
摄像头索引：0
画面分辨率：1280 × 720
目标帧率：15 FPS
置信度阈值：0.50
NMS IOU 阈值：0.45
连续确认帧数：5
```

运行方式：

```bash
cd code/2026code/视觉/视觉1.0
python3 single_demo_en.py
```

指定模型和摄像头：

```bash
python3 single_demo_en.py \
  --model dangerous_target.onnx \
  --source 0
```

使用视频文件：

```bash
python3 single_demo_en.py \
  --model dangerous_target.onnx \
  --source test.mp4
```

为了减少单帧误检，程序不会在第一次识别到目标时立即确认，而是要求同一类别连续出现 5 帧。达到要求后，该类别会被加入已确认目标列表。

运行窗口中会显示：

* 检测框；
* 类别名称；
* 置信度；
* 已确认目标；
* 各类别连续检测进度。

按 `q` 键退出程序后，会在当前目录生成带有时间戳的 CSV 文件，用于保存最终确认的危险品类别。

当前标签使用拼音显示，是为了避免部分 Ubuntu 环境下 OpenCV 显示中文乱码。标签的顺序必须与模型训练时的类别顺序完全一致，不允许随意调整。

### `labeling.py`

这是一份基于 PyQt5 的图像标注工具，主要功能包括：

* 批量导入图片；
* 缩略图浏览；
* 鼠标拉框；
* 移动标注框；
* 删除单个标注框；
* 清空标注框；
* 保存标注；
* 加载 `.pt` 或 `.pth` 权重。

主要依赖：

```bash
pip install pyqt5 pillow torch
```

运行方式：

```bash
cd code/2026code/视觉/视觉1.0
python3 labeling.py
```

当前程序保存的标注格式为：

```text
x1 y1 x2 y2
```

其中坐标是基于原始图像尺寸恢复后的像素坐标。

需要特别注意：这不是标准 YOLO 的：

```text
class_id x_center y_center width height
```

格式。如果后续使用 YOLO 训练，需要先补充类别编号并进行坐标归一化转换，不能直接把当前生成的 TXT 文件放入 YOLO 数据集训练。

另外，当前代码虽然能够加载 `.pt` 权重，但还没有把模型推理结果接入自动标注流程，目前仍然以人工拉框为主。后续可以加入模型预标注功能，再由人工修正检测框，以提高数据标注效率。

---

### `labels.docx`

用于记录和对照危险品类别标签。

修改类别时，应当同步修改：

* 标签说明文档；
* 训练数据类别编号；
* 模型配置文件；
* `single_demo_en.py` 中的 `CLASS_NAMES`；
* 推理结果保存和显示逻辑。

7. 增加任务超时、状态回退和人工接管；
8. 增加日志记录与 rosbag 数据采集；
9. 在仿真中完成全流程后，再进行真机测试。

## 注意事项

自动飞行代码必须先经过 SITL 仿真验证，再进行真机测试。

真机测试前应当确认：

* 飞控模式和固件正确；
* MAVROS 已连接；
* 本地位置数据正常；
* 高度和坐标系方向正确；
* 起飞区域无人员和障碍物；
* 遥控器能够随时切换模式并人工接管；
* 已准备紧急降落和上锁命令；
* 首次测试应拆除桨叶检查服务和状态切换逻辑。

不要在没有安全员、没有人工接管手段或坐标系尚未验证的情况下直接运行自动飞行程序。

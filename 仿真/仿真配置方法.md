以下配置针对ros2 humble，ubuntu22.04系统，nvidia显卡。（前两点必须满足，第三点不满足以下教程应该也适用）
以下教程建议全程禁用 conda 及其他非 ArduPilot 自带的虚拟环境，ArduPilot 官方脚本创建的 venv 会自动管理，无需手动干预.特别提醒：即使是conda安装后自动启动的base环境也不可以，使用conda deactivate退出base环境。
0．退出虚拟环境
bash
conda deactivate
conda config --set auto_activate false
使用命令行conda config --set auto_activate false配置 conda 不自动激活 base，这样不用每次开新终端时都执行conda deactivate。建议：不仅配置环境的时候不要使用虚拟环境，运行仿真的时候也不要使用虚拟环境。（特别是conda会对ros2 gazebo等这些硬件相关的工具的环境变量造成巨大的篡改，导致难以解释和解决的错误；即使是venv也很费事，为了简单就禁用虚拟环境吧）
1.配置Gazebo Harmonic
对于gazebo的版本选择，有gazebo Classic（具体来说是gazebo 11），gazebo Harmonic和gazebo Fortress。对于ubuntu22.04，其实Fortress才是LTS（长期支持更新的稳定版本），但它和ardupilot不兼容；另外gazebo 11并不好用，所以我们最终选用gazebo Harmonic。
bash
sudo apt-get update
sudo apt-get install curl lsb-release gnupg # 依赖工具

sudo curl https://packages.osrfoundation.org/gazebo.gpg --output /usr/share/keyrings/pkgs-osrf-archive-keyring.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/pkgs-osrf-archive-keyring.gpg] http://packages.osrfoundation.org/gazebo/ubuntu-stable $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/gazebo-stable.list > /dev/null

sudo apt-get update

sudo apt-get install gz-harmonic
运行以上命令行之后以后每次sudo apt update可能会出现一个warning，这是正常现象（由于这里使用的加入密钥的方法比较原始，后续可能会改进一下这里，使用现代加入密钥的方法，但目前为了快速推进项目，先留个坑）

2 配置ardupilot
2.1前置准备
ArduPilot 对 Python 版本和工具链有严格要求，需先完成基础配置：
bash
# 1. 安装系统核心依赖
sudo apt update && sudo apt install -y git wget python3-pip python3-venv gcc-multilib g++-multilib

# 2. 克隆 ArduPilot 源码（建议放在用户目录，避免权限问题）
cd ~
git clone --recurse-submodules https://github.com/ArduPilot/ardupilot.git
cd ardupilot

# 3. 切换稳定分支（推荐 4.5 版本，兼容性最好）
git checkout Copter-4.5
git submodule update --init --recursive

2.2 安装 ArduPilot 专用依赖（一键脚本）
ArduPilot 提供官方脚本，可自动安装 Python 依赖、工具链和仿真组件，禁止手动安装，避免版本冲突：
bash
# 运行官方依赖安装脚本（关键：自动配置 Python venv）
Tools/environment_install/install-prereqs-ubuntu.sh -y
2.3修改并激活.profile
修改.profile
bah
vi ~/.profile
将以下内容添加到文件末尾（直接复制粘贴即可）：
(科普一下文本编辑器vi的操作：i是插入模式，即按i以后才可以编辑；编辑完成后按esc退出插入模式；然后用键盘输入:wq!保存修改并退出vi（w是写入并保存修改，q是退出，！是强制执行）)

2.4 本地编译（支持仿真/地面站）
编译分为主机仿真版（SITL）和硬件固件版，当前开发涉及 ROS2 与无人机协同，优先编译 SITL 仿真版（无需硬件，可与 Gazebo/MAVROS 联动）。
① 编译 SITL 仿真核心（以无人机 Copter 为例）
bash
cd ~
source .profile

# 进入源码目录
cd ~/ardupilot

# 编译 SITL 版本（自动生成可执行文件）
waf configure

# 编译 ArduCopter SITL 固件
waf build --target bin/arducopter
编译成功标志：输出 Build commands succeeded，生成 build/sitl/bin/arducopter 可执行文件。
如果用waf不行，换成./waf就行了，那就是你的环境变量配置的有问题，好好检查~/.bashrc 和~/.profile。
②编译硬件固件（可选，如 Pixhawk 4）
若需烧录硬件，添加对应硬件板型号即可：
bash
# Pixhawk 4 编译示例
./waf configure --board pixhawk4

./waf build
①和②并非只能选择选择一个，现在处于仿真阶段先选择①，后续根据实际使用的硬件进行②
2-2验证ardupilot是否安装成功（SITL 仿真启动）
编译完成后，启动 SITL 仿真，验证是否可正常运行并输出 MAVLink  数据
bash

cd ~/ardupilot/ArduCopter

sim_vehicle.py -v ArduCopter --console --map
成功标志：弹出控制台(Console)，地图界面（Map）和ArduCopter，终端持续输出无人机状态（如 APM: ArduCopter V4.5.x），端口 14550 正常发布 MAVLink 数据。
3.配置ardupilot_gazebo 插件
3.1前置准备
开一个新终端，安装 ardupilot_gazebo 插件的依赖库
bash
# for Harmonic

sudo apt update

sudo apt install libgz-sim8-dev rapidjson-dev

sudo apt install libopencv-dev libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev gstreamer1.0-plugins-bad gstreamer1.0-libav gstreamer1.0-gl
3.2下载并配置环境变量
bash
git clone https://github.com/ArduPilot/ardupilot_gazebo

配置环境变量
bash
echo 'export GZ_SIM_SYSTEM_PLUGIN_PATH=$HOME/path/to/ardupilot_gazebo/build:${GZ_SIM_SYSTEM_PLUGIN_PATH}' >> ~/.bashrc

echo 'export GZ_SIM_RESOURCE_PATH=$HOME/path/to/ardupilot_gazebo/models:$HOME/path/to/ardupilot_gazebo/worlds:${GZ_SIM_RESOURCE_PATH}' >> ~/.bashrc
注意$HOME指的是/home/你的用户名，比如我的ubuntu系统用户名是zxx，那么我的$HOME就是/home/zxx。
关键点是黄色部分，要替换成ardupilot_gazebo所在的路径中除去/home/你的用户名的部分，比如我的ardupilot_gazebo所在的路径是/home/zxx/ardupilot_gazebo,那么我执行的命令就是
echo 'export GZ_SIM_SYSTEM_PLUGIN_PATH=$HOME/ardupilot_gazebo/build:${GZ_SIM_SYSTEM_PLUGIN_PATH}' >> ~/.bashrc

echo 'export GZ_SIM_RESOURCE_PATH=$HOME/ardupilot_gazebo/models:$HOME/ardupilot_gazebo/worlds:${GZ_SIM_RESOURCE_PATH}' >> ~/.bashrc
3.3编译ardupilot_gazebo 插件
bash
cd ardupilot_gazebo
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=RelWithDebInfo
make -j4

正常的运行结果如下图：

这时对于nvidia显卡可能会出现左侧画面全白，gazebo卡死的情况，这是因为gazebo默认设置LIBGL_ALWAYS_SOFTWARE=0 ，允许 OpenGL 库尝试使用可用的硬件加速（不一定会找到可使用的硬件加速），这就要求你得配置好nvidia显卡的驱动（详细情况我之前写的关于如何安装CUDA的教程）
配置好显卡驱动以后，还要接着配置终端变量
bash1
export __NV_PRIME_RENDER_OFFLOAD=1
export __GLX_VENDOR_LIBRARY_NAME=nvidia
export __VK_LAYER_NV_optimus=NVIDIA_only
第一次没成功的话试试重启电脑，再重新export和gz sim，如果还没有解决问题的话，还有最后一招
bash
export LIBGL_ALWAYS_SOFTWARE=1
LIBGL_ALWAYS_SOFTWARE=1时强制 OpenGL 使用软件渲染而不是硬件加速渲染，这对CPU负担很重，但基本可以解决问题。
以上用到export的命令，当每次打开新终端的时候还要重新运行才会起效

# 03 · 接入与实验计划

## 先固定可复现环境

把整个 `ws_offboard_guided_profiles/` 复制到 Ubuntu 22.04 / ROS 2 Humble 目标机，保持包名 `cuadc_full_mission_20260803`。不要在同一终端加载另一个同名 V16 工作空间的 `install/setup.bash`，否则可能运行旧二进制。

从该工作空间根目录执行：

```bash
source /opt/ros/humble/setup.bash
rosdep install --from-paths src --ignore-src --rosdistro humble -r -y
python3 scripts/validate_source.py
bash scripts/build_onboard.sh
bash scripts/verify.sh
source install/setup.bash
ros2 pkg prefix cuadc_full_mission_20260803
```

依赖、模型与设备配置见 [环境说明](../ws_offboard_guided_profiles/environment/README.md)。最后一条返回的包路径应位于此次工作空间。编译和离线测试不会连接飞控、启动视觉或发送舵机命令。离线结果只能证明测试覆盖到的软件行为，不能证明空中切换稳定。

## 实验分层

| 次序 | 范围 | 本轮要回答的问题 | 退出条件 |
| --- | --- | --- | --- |
| 1 | 纯源码、单元与离线回归 | 配置是否合法、参考连续、事务是否按确认推进 | 所有必要测试通过 |
| 2 | 同版本 SITL，本地阶段模式 | 切换期间 setpoint 连续、参考和实际运动符合预期 | 阶段、低速门控、超时、接管均可复现 |
| 3 | 同版本 SITL，飞控改速 | 当前 GUIDED 子路径是否采用命令速度 | ACK 和日志响应分别验证 |
| 4 | 同版本 SITL，PID 事务 | 部分成功、拒绝、丢 ACK、超时、恢复是否处理正确 | 无无限重试或未知结果并发回滚 |
| 5 | 实机台架与低速试验 | 设备配置、载荷、真实运动与模型差异 | 记录可追溯并达到预先定义指标 |

当前未给出实机固件完整版本、飞控参数导出和已验证载荷 PID。完成前四层后才能对第五层作有依据的判断；本版不在默认配置中代填这些信息。

同时核对 `GUID_OPTIONS` 和实际使用的 GUIDED 控制路径。状态机处理已知的模式进入、起飞到位置控制切换，并重新申请配置；另一个程序在同一 GUIDED 模式内改用不同 setpoint 路径时，本版无法直接观测飞控内部子模式。任务 setpoint 应由本状态机统一发送。启用飞控改速时，需要在同版本 SITL 中验证当前路径实际采用新限制，不能用服务接受结果替代飞行响应检查。

## 同版本 SITL 适配

本交付包含任务工作空间，没有把 ArduPilot SITL、Gazebo 或比赛场景全部打包。使用你们已有的仿真工程，并按实际固件版本固定 ArduPilot 源码。先确认飞控连接到 `mavros` 命名空间、里程计有效，并提供原状态机所需的视觉消息与心跳；没有感知输入时按原等待/故障流程运行，不应绕过条件来取得一次“成功”。

核对服务：

```bash
ros2 service list -t
ros2 service type /mavros/param/set
ros2 service type /mavros/param/pull
ros2 service type /mavros/cmd/command
ros2 topic hz /mavros/setpoint_position/local
ros2 topic hz /mavros/local_position/odom
```

先保留 `guided_fcu_enabled=false`，只测试本地阶段配置。使用单独的仿真配置文件记录每次覆盖，不覆盖交付的默认关闭实飞配置。在仿真中明确启用飞行总开关后，按原任务入口启动；飞控与视觉启动方法取决于现有仿真工程。

速度与加速度指令有 `GUID_TIMEOUT` 机制，需要维持对应 setpoint 流；本版仍沿用位置参考发布，异步接口设计也不得阻塞该定时器。[官方 GUIDED 指令说明](https://ardupilot.org/dev/docs/copter-commands-in-guided-mode.html)

## 必须覆盖的切换与故障

1. 巡航 → 搜索 → 接近 → 对准 → 投放 → 侦察 → 返航，核对每个实际任务分支是否选择了正确配置。
2. 高速进入慢阶段：先以旧加速度减速，参考归零后实际运动仍未稳定时不得放行。
3. 里程计冻结、延迟或速度噪声：稳定时间重置，无法满足门槛时在预算内终止并进入降落处理。
4. 事务正常 ACK、显式拒绝、回值不匹配、客户端超时、MAVROS 内部超时、迟到回应、飞控断连、人工接管。
5. 三项 PID 中前两项已成功、第三项失败；核对中间组合和恢复过程，未知结果时不得并发抢写恢复。
6. 两瓶投放流程推进：`full / single / empty` 标签仅随原流程更新，故障不得伪造完成计数；视觉失效与原超时投放回退单独验证。

对应软件回归与真实执行结果见 [验证记录](04_验证记录.md)。测试使用的模拟成功/失败是软件场景，不是实机飞控证据。

## 采集与验收

每轮保存此次运行 YAML、程序版本、ROS/MAVROS 版本、飞控完整固件版本、飞前和飞后参数导出、任务日志、里程计、setpoint、视觉时间戳、飞控 DataFlash。原工作空间的记录与复盘工具可继续使用，邮件功能不属于本提案执行范围。

验收标准应在实验前填定，建议比较相同路线、载荷和外界工况下的阶段切换时间、参考最大跳变、setpoint 最长发布间隔、实际水平/垂直速度、超调、视觉末端误差和投放结果。位置参考差分得到的是参考速度，不可当成机体实际速度；两者分别统计。没有用本次缺失的试飞数据生成通过指标。

满载、单瓶、空载先使用同一套飞控内环验证本地阶段设置；若确实存在可重复的控制性能缺口，再设计载荷增益组。需要比较完整组和所有可能出现的混合组，并考察积分历史、饱和、振荡、舵机动作扰动和切换后恢复时间。交付中的标签本身不足以确认真实载荷。

## 实机启用与落地复核

独立检查设备序列号、飞控地址、舵机通道和 PWM、相机/投放口外参、路线标定、速度高度及原投放超时回退。先完成台架和低速验证，记录人工接管处理；把适配后的运行配置与原交付分开保存。

只需要任务阶段快慢变化时，保持飞控参数事务关闭。确认有必要且已有同版本验证后，才填写人工固件声明、白名单和已验证数值。飞控参数写入可能持久保存，每次异常后落地读取实际值，并与快照比对后再决定下一轮。ACK 成功不能省略运动响应检查，进程重新启动也不能省略飞控状态核对。

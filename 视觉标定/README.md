# 双投放视觉标定原理

<img width="1920" height="846" alt="4e6728b8137299b02fa78e30cf7a9bf8" src="https://github.com/user-attachments/assets/dca0ebdf-1387-450e-a7ec-2207d8d622c7" />

八月底重新调整投放策略时，我们开始尝试视觉伺服下的室内投放标定。到九月初，中、大桶在当时的测试条件下已经有了比较好的投放表现，小桶仍然差一些。继续检查，既发现了外参使用的问题，也发现投放舵机连杆中心和水瓶限位不在同一轴线上。这个过程在[备赛日志](https://github.com/Accelerate11/2026CUADC/blob/main/%E6%97%A5%E5%BF%97.md)里有记录。

这件事让我比较明确地认识到，桶能识别出来以后，后面仍然有不少工作。相机看到的中心、飞控使用的飞机位置、两个水瓶实际离开机构的位置，并不在同一个地方。只量一组机械尺寸，或者让桶一直留在画面中央，都不能直接说明水瓶会落进桶里。

这里把标定原理和实际操作放在一起，方便后面的同学接着使用。涉及具体坐标、参数和画面含义的地方，按 V16 的实际实现说明。换了代码版本、相机安装方向或者投放机构以后，需要重新核对，不能只把这架飞机的数值复制过去。

## 先把几个坐标系讲清楚

开始调参数之前，先确认前后左右。这个地方一旦弄反，后面仍然可能把某一个点调得看起来很准，但是换到另一个投放口，或者挪一下桶，误差就会重新出现。

相机使用 Optical 坐标，V16 的视觉输出和投放口参数使用 FCU FRD。ROS 中还会见到 FLU，三者的方向如下。

| 坐标系 | +X | +Y | +Z |
| --- | --- | --- | --- |
| 相机 Optical | 图像向右 | 图像向下 | 沿镜头光轴向前 |
| 机体 FRD | 机头前方 | 机体右方 | 机体下方 |
| 机体 FLU | 机头前方 | 机体左方 | 机体上方 |

我们的 D435i 朝下安装，所以相机光轴朝向地面。V16 正式任务 YAML 中的安装矩阵对应“图像左侧是飞机前方，图像上方是飞机右侧”，图像右侧和下方分别对应飞机后方、左方。这个对应关系由安装和参数决定，换一块支架、换一个安装方向，就要重新验证。

实际检查时固定飞机，分别把桶向机头前方和机体右方移动，视觉输出的 FRD `x`、`y` 应分别增大。桶在飞机下方时，FRD `z` 通常为正。这里看的是物体相对于飞机的运动，移动飞机时不要把方向又看反了。

V16 的 `/perception/drop_buckets_body` 使用 `fcu_body_frd`，`payload_release_offsets_body_m` 也按 FRD 填写。C++ 状态机在入口处把它们转换成内部使用的 FLU，再参与世界坐标计算：

```text
x_flu =  x_frd
y_flu = -y_frd
z_flu = -z_frd
```

因此，看到内部计算使用 FLU，不代表 YAML 也要跟着改成 FLU。填参数时以实际接口为准，尤其是投放口在飞机右下方时，FRD 的 `y`、`z` 都是正数。

## 相机和两个投放口，各自要标定什么

相机外参描述相机光学中心相对于机体参考原点的位置，以及相机三个轴朝向哪里。最基本的关系是：

```text
P_body = R_camera_to_body · P_camera + T_camera_to_body
```

`R` 是旋转，`T` 是平移。V16 中对应 `camera_to_body_rotation` 和 `camera_to_body_translation_m`。平移的单位是米，测量时要明确光学中心和机体参考原点，不能一边量的是外壳边缘，另一边填的是镜头中心到飞控的位置。

投放口外参则是两个真实释放点相对于同一个机体原点的位置。这里把一号、二号投放口记为 P1、P2，每个点都有自己的 `x/y/z`：

```text
P1 = [x1, y1, z1]
P2 = [x2, y2, z2]
```

测的是水瓶实际离开机构的位置。舵机轴心、支架中心和水瓶释放点可能并不重合，前面小桶精度的问题就提醒过我们这一点。两边机构也分别测，不要因为图纸上对称，就把另一边直接写成镜像值。

V16 保存的原机参数是下面这一组，单位为米，坐标为 FRD。它用于说明参数排列方式，不能当作另一架飞机的标定结果。

```yaml
payload_release_offsets_body_m:
  [0.029, 0.070, 0.320,
   -0.031, -0.065, 0.320]
```

前面三个数对应一号右前投放口，后面三个数对应二号左后投放口。任务节点和视觉节点都有这项参数，后面调整时要保持一致。

其他标定说明中可能会用 `camera_xy_bias` 描述稳定的 XY 残差修正。V16 这套正式接口没有一个同名的独立参数，往 YAML 里加上这个名字，并不会自动得到补偿。确实需要修正时，先确认误差来源和代码实际使用的外参，避免同一个偏差在相机平移、额外 bias 和投放口位置里各补偿一次。

## 画面上的三个点，分别在表示什么

室内预检画面中，绿色十字标记目标中心，橙色十字对应一号右前投放口 CH7，洋红色十字对应二号左后投放口 CH8。我们希望在物理上把桶放到某个投放口正下方以后，画面中的绿色十字也能与对应准星重合。

这里需要把 V16 的实现说清楚。绿色 `TARGET CENTER` 直接画在检测框中心，程序再结合深度和相机外参计算三维坐标。虽然包里保留了分割、椭圆等相关代码，当前这条正式路径使用的是检测框中心，不能把这个绿点写成已经经过分割和椭圆拟合的真实桶口中心。检测框本身偏了，绿点也会跟着偏。

两个投放准星按机构位置计算。程序取对应投放口的机体 `x/y`，配上估计的桶口平面 `z`，再通过相机外参的逆变换和相机内参投回图像：

```text
P_marker_body = [x_release, y_release, z_rim_body]
P_marker_camera = Rᵀ · (P_marker_body - T)

u = fx · X_camera / Z_camera + cx
v = fy · Y_camera / Z_camera + cy
```

这也解释了为什么准星不能固定成某个像素。机构离机体中心几厘米，这个机械距离不变，但相机离桶越远，它在画面里占的像素通常越少。更换高度以后，应该重新计算投影，而不是手动把十字挪到看起来合适的位置。

准星的机体 `x/y` 不能随着检测到的桶一起移动，否则画面会把真正的对准误差藏起来。与此同时，V16 这段预览按机体 z 方向构造投影点，没有用实时姿态求重力方向的铅垂线，所以这一步要把飞机架平。它也没有用投放口自身的 `z` 来决定准星位置，因此十字重合不能单独证明投放口的三维外参全部正确。

## 高度和深度，先弄清楚量的是哪个平面

桶口、桶底和桶外地面会出现在同一幅深度图里。飞机靠近以后，框中心可能看到桶内，也可能看到其他表面。调 Z 之前，要先知道程序现在拿到的深度来自哪里。

V16 当前路径优先从检测框外一圈采样，估计桶周围的地面深度，再结合桶高恢复桶口几何。原参数 `bucket_height_m` 为 0.30 m。外环采样不足时还有中心深度回退，这种情况下要一起检查原始深度和回退原因，不能直接把异常结果当成安装尺寸发生了变化。

飞机水平、桶和飞机参考高度使用同一块地面作为基准时，可以按下面的关系检查：

```text
z_rim_body = z_ground_body - h_bucket
H_body - z_rim_body ≈ h_bucket
```

这里 `H_body` 是机体参考原点离地的高度，`z_rim_body` 是桶口在 FRD 中的向下距离。V16 默认处理路径中的普通 `body_z` 是地面参考点，不能直接把它当成桶口 z，再用“离地高度减 body_z”去判断桶高。

相机离地高度、机体原点离地高度、飞控相对起飞点的高度，也不是同一个量。测量和比较时要把相机平移、参考原点和地面是否同高交代清楚。飞机有明显倾斜时，上面这个沿机体 z 的简化关系也需要重新处理。

另一个容易混的参数是 `bucket_height_compensation_ratio`。V16 原值为 0.85，只用于表观桶径换算；准星和桶口几何仍使用完整的 0.30 m 桶高。不要为了让 XY 准星重合，顺手把桶高、深度和桶径补偿一起改掉。

## 实际标定按这个顺序做

先把飞机固定好，卸桨、不解锁，保持机体水平，相机和机构都处于实际使用时的安装状态。模型、分辨率、深度处理和曝光也尽量与正式任务一致，否则室内调好的是另一套视觉结果。

使用 V16 开源工作区时，先按工作区说明完成环境配置和编译，再从工作区根目录启动预检：

```bash
bash indoor_projection/preflight_projection.sh
```

这个入口只启动视觉节点，不启动 MAVROS 或任务状态机。手动曝光可以在命令末尾传入对应数值；这里的曝光需要按实际光照调整，不统一抄一组室内值到外场。

1. **先检查方向和深度。** 固定飞机，前后左右移动桶，确认坐标增减方向，再核对地面与桶口的高度关系。这两项有问题时，先处理它们。
2. **测量 P1。** 从一号真实释放点垂下一根细线，在线端悬挂重物，把桶口中心放到这条铅垂线下。机体水平时，桶口中心的真实机体 XY 应与 P1 的 XY 一致。
3. **连续记录一段数据。** 飞机和桶保持静止，采样 3～5 秒，记录目标坐标、准星偏差、当前高度和使用的参数。先保存原始结果，不急着把每一项都调到零。
4. **用同样的方法测 P2。** 两个投放口分别取得物理基准，再一起看误差。不要只根据一号投放口的一帧画面，决定整架飞机的相机外参。
5. **按误差来源修改一类参数。** 先处理共同的相机外参问题，几何关系稳定以后，再检查单个机构的位置。每次记下改了哪个值、为什么改。
6. **按 P1 → P2 → P1 重新验证。** 确认第二个点调好以后，第一个点仍然准确；再挪动桶、改变一些视距，看看结果能不能重复。

比较误差时，真值和视觉结果必须使用同一坐标系、同一目标平面。例如桶口已在 P1 铅垂线下，可以记录：

```text
Δx = x_P1 - x_rim_measured
Δy = y_P1 - y_rim_measured
```

这些残差先用于判断问题。要把它们用于修正，还要确认被修改的参数处于哪个坐标系、在哪一步生效，不能看到一个正数就直接加到任意偏移项上。

多帧数据可以分别取中位数，并用 MAD 看波动大小：

```text
中心值 = median(x)
MAD_x = median(|x - median(x)|)
```

`y/z` 同理。MAD 小说明结果比较稳定，但一个稳定偏了几厘米的结果，MAD 也可能很小，所以稳定性和相对物理真值的残差要分别看。毫米级残差可以作为静态调试目标，例如先争取 XY 各在 5 mm 以内；这需要测量条件支持，也不代表实飞一定达到同样精度。

## 两个投放口都测完，再判断该改哪里

两个投放口的原始记录都尽量留下来。只盯着当前这一个十字调，很容易出现一号调好、二号又偏，修完二号再回来改一号，最后相机和机构参数一起漂移。

| 观察到的现象 | 优先检查的方向 |
| --- | --- |
| P1、P2 大致同方向、同大小偏移 | 共同的相机平移误差、参考原点偏差，以及目标中心是否存在稳定偏差 |
| 两点偏差方向不同，或连线方向、间距不合理 | 相机旋转、深度尺度、两个机构的实测位置 |
| 一个点较准，另一个点明显不准 | 对应机构的释放点、限位和装配，同时用更多位置复查相机外参 |
| 误差随视距明显变化 | 相机安装角、深度和目标中心随尺度变化的情况 |
| 静止时结果也不断跳动 | 检测框、深度质量、光照、曝光及安装是否稳定 |

这些是排查顺序，不能只凭一种现象就把原因定死。两个点反向偏，不一定就是 yaw；一个点刚好重合，也不代表相机外参已经全部正确。我们之前遇到过机械限位的问题，所以检查代码的同时，也要看水瓶究竟从哪里离开机构。

同样，一次单点重合不能同时确定旋转和平移。在旋转已经可信的前提下，它可以帮助检查平移残差；两个已知点能多提供一组方向和距离关系，但仍不足以唯一确定完整的三维外参。如果用相机参数和投放口参数同时去解释同一组误差，就更需要独立的机械测量和其他位置验证。

## 换高度以后，哪些量该变，哪些量不该变

相机和机构装在机架上，它们相对于机体的平移是机械长度。相机在参考原点前方 3 cm，不会因为飞机从 0.9 m 升到 1.3 m，就变成另一个按比例放大的距离。投放口位置也是一样。

安装角误差产生的横向偏差，会随观测距离变化。在简单几何条件下，可以用“距离 × tan(角度误差)”估计它的量级。如果低处比较准，升高以后偏差明显增大，应该检查旋转、深度和目标中心的变化，而不是直接按高度比例放大平移或 bias。

最终还是要在实际投放的工作高度附近验证。V16 完整任务的投放高度为相对起飞点 1.0 m，这个参数不能直接当成相机到桶口的距离。实际布置标定高度时，还要核对当前任务配置、地面高度和机体安装尺寸。条件允许时，再选几个附近高度交叉验证。

静态标定完成以后，还要进入飞行验证。飞行中投放口的位置与机体姿态有关，几何关系可以写成：

```text
P_release_world = P_vehicle_world + R_body_to_world · P_release_body
```

公式中的机体系要与旋转矩阵一致，FRD 参数需要按程序接口完成转换。这是检查刚体几何的一般关系，不能据此认为现有程序的每个控制分支都完整实现了同样的三维补偿。V16 粗对准按任务 yaw 处理平面杆臂，细对准另有姿态修正，需要分别核查。室内水平画面上的准星重合，并没有验证这整段动态过程。

V16 还要把图像曝光时刻与飞机的位置、姿态对齐。悬停时不明显的时间差，在前进、下降和姿态变化时都可能变成目标位置误差。再加上风、释放延迟、水瓶运动和机构重复性，静态残差只是后续投放精度的一部分。九月初某一阶段投得很准，也不能替代换场地、换风况以后的验证。

## 标定结束以后，把参数和记录一起留下来

最终要留下的是一套能与实际飞机对应的参数：相机旋转和平移、P1 和 P2 的真实释放点，以及验证它们时使用的条件。至少记下机体和机构版本、相机安装、坐标系、单位、测量基准、标定高度、模型与曝光，以及两边的多帧残差和视频。

还要确认改动真的进入了正式任务。V16 整理版的室内投影入口读取：

```text
src/cuadc_full_mission_20260803/config/mission_real.yaml
```

完整任务和仅投放入口分别读取：

```text
full_mission/mission.yaml
drop_only/mission.yaml
```

这些文件不会因为室内标定完成就自动同步。确认过的相机外参要写入实际使用的视觉配置，`payload_release_offsets_body_m` 则要同时核对任务节点和视觉节点两处。不要把整个配置文件互相覆盖，避免把其他任务参数也一起带过去。

运行时还要保存本轮参数副本和实际启动命令。相机、模型和推理设备可能由启动参数或环境变量覆盖，单看一个 YAML 不一定就是这次运行的全部配置。更换了机构、移动了相机或者修过飞机，也要回到 P1、P2 的物理基准重新检查。

我们已经花过不少时间去区分视觉、控制和机械各自的问题。后面接手的同学如果能从一开始就把坐标、实际释放点和参数来源记清楚，再遇到投不准的情况，至少能知道应该从哪一层查起。
